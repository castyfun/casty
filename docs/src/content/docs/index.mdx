<div class="lede">

casty puts a [Snapchain](https://snapchain.farcaster.xyz) read node, a full copy of Farcaster, on a
host you control, and gives you a client that talks to nothing else: a terminal command and a page
for the browser and the phone. Your feed, mentions and threads are read from your node; your
casts, replies, likes, recasts and follows go out through it. No hosted API stands between you and
the network, so there is no API key to get and no rate limit to meet.

</div>

## Start with one command

<div class="ways">
<div class="way">

### A new node of your own

A server with a 2 TB volume and a firewall on Hetzner or AWS, Snapchain on it, the client on your
machine, and the page on the host behind HTTPS. The node syncs for a few hours.

```sh wrap
git clone https://github.com/castyfun/casty.git && cd casty
./scripts/deploy.sh --fid <your fid> --domain node.example.org
```

Already have a Linux machine with 2 TB free? Add `-- --host user@ip`.

</div>
<div class="way">

### casty on a node that already runs

No server: casty connects to any Snapchain node, one of yours on another machine or a public one,
and remembers it. Ready in a minute.

```sh wrap
git clone https://github.com/castyfun/casty.git && cd casty
./scripts/2-client.sh --node https://snap.farcaster.xyz:3381 --fid <your fid>
```

Then `./bin/casty web` and, under you, "add a key with your wallet".

</div>
<div class="way">

### Let an agent do it

Paste [one prompt](agents/) into Claude Code, Codex, Cursor or another coding agent. It reads
[llms.txt](https://castyfun.github.io/casty/llms.txt), asks which of the two you want, and never
asks for your seed phrase.

```text wrap
Set up casty for me: https://github.com/castyfun/casty.
Read https://castyfun.github.io/casty/llms-full.txt first.
...
```

## How it fits together

<Architecture />

Reads come from your node, so the feed is as fast as the machine it runs on. Writes are signed on
your machine with an app key only casty holds, and your node relays them to the validators. The
key is added with one signed message, approved by your wallet in the browser: no transaction, no
gas, no Ethereum RPC.

## What you get

<div class="features">

- **Three scripts and one command.** `0-provision.sh` rents the server or checks yours,
  `1-node.sh` installs Snapchain and waits for its sync, `2-client.sh` installs `casty` and adds a
  key. `deploy.sh` runs them in order and picks up where a run stopped.
- **A terminal client.** `casty feed`, `casty cast`, `casty like 2`: plain text for you, `--json`
  for scripts, numbers that carry over from one command to the next.
- **A page for the browser and the phone.** The feed, threads, mentions, profiles and a compose
  box, light and dark, with keyboard shortcuts on a laptop and an install-to-home-screen on a
  phone.
- **Your node, anywhere.** `casty serve` puts the page on the node's host behind HTTPS, with a
  feed index that answers at once and push notifications for mentions and replies.
- **Keys you can see.** Every app key of your account, what it may sign, when it lapses, and
  revocation from the terminal or with the key itself.
- **Tested without a node.** A mock Snapchain node checks every signature, so the client, the
  scripts and the page run their checks offline in CI.

</div>

## What you need

- A Farcaster test account: an fid with at least one storage unit, and a wallet that holds the
  address it is registered to, or that address's seed phrase. casty uses the phrase once, to
  sign the key request, and never writes it to disk.
- A host. Either credentials for Hetzner Cloud (`HCLOUD_TOKEN` and the `hcloud` CLI) or AWS (the
  AWS CLI v2 and a profile or access key), or SSH access to a machine you already have that can
  run Docker. See [A node at home](home-node/) for the last case.
- An SSH key pair, by default `~/.ssh/id_ed25519` and `~/.ssh/id_ed25519.pub`.
- On your machine: `ssh`, `curl` and `jq`. Node.js 22.12 or newer only to build the client
  yourself (`2-client.sh --from-source`). macOS and Linux work; on Windows, run the scripts in
  WSL2.

The node host needs what Snapchain asks for: 16 GB RAM, 4 vCPU, 2 TB of free disk and a public
IP ([getting started](https://snapchain.farcaster.xyz/getting-started)). On a rented host, step 0
picks the server and the volume, and step 1 checks the host before it installs anything.

## How long it takes

Step 1 takes the longest: on its first start the node downloads a snapshot of several hundred
GB, then catches up on the blocks since that snapshot. Expect hours.
`1-node.sh` waits and prints how far behind the node is after each check. Pressing Ctrl-C ends
only the wait; the node keeps syncing, and `./scripts/1-node.sh status --wait` picks the wait up
again.

## What it costs

casty does not know your provider's prices. A real `0-provision.sh` run lists the server, volume
and firewall it is about to create, says they are billed until you delete them, and goes ahead
only once you type the server name back. `./scripts/0-provision.sh --destroy` deletes all three.

## Try it without a node

The repository ships a mock Snapchain node that serves the same HTTP API from fixtures and checks
the signatures on every message submitted to it. With it, the whole client runs offline:

```sh
pnpm install --frozen-lockfile
pnpm demo
```

`pnpm demo` starts the mock on a free port, adds an app key with the BIP-39 test phrase
`test test test test test test test test test test test junk`, reads the feed with and without
one app's casts, publishes a cast, likes one, and deletes its throwaway config at the end. The
fids in the fixtures start at 2000000001 and belong to no one.

`pnpm demo:web` does the same setup, then serves [casty web](web/), the browser and phone page,
on a free port until you press Ctrl-C.

## One command

```text
Usage: deploy.sh [--domain <name> | --tailscale] [--read-only] [--fid <fid>] [--from-source]
                 [--env <file>] [--yes] [--dry-run] [-- <0-provision.sh options>]

  Runs, in order: 0-provision.sh (unless --env's file already describes a host; with --domain,
  again on that host to open 80 and 443), 1-node.sh (the node, the wait for its sync, the
  tunnel), 2-client.sh (the client, an app key, the feed) and, with a front named, 1-node.sh
  serve. Every step is safe to run again: the same command picks up where a run stopped.

  --domain <name>   serve the page on the host as https://<name> (Caddy; opens 80 and 443)
  --tailscale       serve it as the host's name on your tailnet instead
  --read-only       a page that reads only: no app key or passphrase leaves this machine
  --fid <fid>       no seed phrase: 2-client.sh --fid; add the key in ./bin/casty web with your
                    wallet, then run the same command again for the page on the host
  --from-source     build the client here with Node and pnpm instead of downloading it
  --env <file>      node.env to write or read (default: node.env)
  --yes             do not ask before creating anything
  --dry-run         print what provisioning and the node would run; the client is skipped
  -- <options>      passed to 0-provision.sh, e.g. -- --provider aws --region eu-west-1

Exit codes: 0 ok, 2 bad arguments, otherwise the code of the step that stopped.
```
